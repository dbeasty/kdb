# v0.8.2

**The server code is identical to v0.8.1.** v0.8.1 published its container image and the
`@kdb/client` npm package, but not its binaries, jars or Go source bundle: the release job that
builds them runs the Go tests inside the embeddable bundle, and one test there
(`TestInstallSnapshotMemoryIsBounded`) failed on the single-CPU runner. The test, not the server,
was wrong (#299), so this release republishes the same code with every artifact.

Everything in `docs/releases/v0.8.1.md` applies: the fix for the v0.8.0 memory regression with
many small namespaces, the corrupt-SSTable-footer fail-fast, and the `graph.chunkBytes` setting.

## What changed since v0.8.1

**A memory test no longer relies on the bug v0.8.1 fixed (#299, test only).** The test bounds
what stays live after a snapshot install. On v0.8.0 the install freed the node's original commit
graph, whose genesis held a full 1 MiB chunk, and that freed megabyte hid the installed tree's
real cost; v0.8.1 made the chunk small, so with one CPU the test saw ~740 B/doc against a 600 B/doc
limit. Exact heap diffs show the same memory on v0.8.0 and v0.8.1 and no document bodies held.
The limit is now half a body per document, which still catches held bodies.

## Upgrading

From v0.8.1: nothing to do if you run the container image or `@kdb/client` 0.8.1; they are the
same code. Use v0.8.2 for binaries, jars and the Go source bundle. From v0.8.0: see v0.8.1's notes.
