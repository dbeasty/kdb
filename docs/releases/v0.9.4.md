# v0.9.4

A storage fix: a sstable left without a footer by a writer that died no longer stops compaction
for its namespace. There is no data migration and no format change; v0.9.3 opens a store written
by v0.9.4.

## What changed since v0.9.3

### Server

- **Memtable flushes publish by rename** (#342). A flush now writes its table under
  `sstable-partial/` and renames it into `sstable/` only once the footer is written. Before, a
  flush wrote straight to the final name, so a process that died between the last block and the
  footer left a table that every open registered and that no merge could read. Merges already
  worked this way since v0.8.0.
- **Merges set aside a table that was provably never finished** (#342). When a merge input has
  whole, valid blocks followed by nothing or by a torn footer, the merge moves it to
  `ns/<ns>/sstable-unfinished/<level>/<id>` (kept, not deleted), logs
  `set aside sstable …`, and merges the rest. Lookups already skipped such a table, and its writer
  never returned, so nothing depended on it. Any other corruption still stops the merge, as before.
  On a copy of zolik's affected volume, v0.9.3 merged nothing (`footer declares a 456541016-byte
  index in a 47983-byte table`) and v0.9.4 set the one table aside and merged the other 17.
- **The footer's magic and repeated length are checked** (#342). Without the check, a footerless
  table whose last bytes happened to look like a small index was parsed as one.

### Benchmarks

- `BenchmarkNamespaceFootprint` (embed) reports live heap per namespace for each commit-graph
  mode. 5,000 namespaces of 20 commits: about 160 KB each for `graph=kdb+file` and `graph=kdb`
  (v0.8.0: about 1.2 MB, before v0.8.1's growing graph chunks).

### Tests

- The syncnode mesh tests rebuild the mesh on fresh ports when another process takes a reserved
  port before the node binds it.
- `TestHistoryTreesChargedByTheirDelta` waits for pending slab cleanups before both heap readings.
  Earlier tests' cleanups were being counted as freed by this one, which failed the Windows
  shards (including the 2026-11-22 nightly).

## Upgrading

Replace the binary or image. A store that holds an unfinished table logs one `set aside sstable`
line at its first merge; the file is kept under `sstable-unfinished/` and can be deleted once you
no longer want it for inspection.

Rolling back to v0.9.3 is safe: it does not read `sstable-unfinished/`, and it clears
`sstable-partial/` before each merge, as it always has.

## Known issues

- Kotlin's sstable writer still writes under the final name, so a Kotlin process killed mid-flush
  can leave the same kind of table. zolik runs Go only.
- npm: the `npm-client` job 404'd on v0.9.2 and v0.9.3 even with the trusted publisher registered;
  if it does again, the client tarball on this release is published by hand.
